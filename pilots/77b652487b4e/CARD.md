## Hypothesis

On a fixed bursty arrival trace, a depth-proportional worker scaler (1–6 workers,
poll every 1 s, 1.5 s scale-up delay, 5-poll scale-down hysteresis) achieves
p95 task turnaround ≤ 70% of the fixed-3-worker always-on baseline while consuming
no more total worker-seconds than the baseline.

## Primary metric

**p95 task turnaround, in seconds** (completion time − arrival time, 95th
percentile over all 150 tasks). Win = treatment p95 ≤ 0.70 × baseline p95 AND
treatment worker-seconds ≤ baseline worker-seconds. Both thresholds fixed here,
before either arm ran. Worker-seconds is a guard metric, not a second primary:
a scaler that wins latency by simply running 6 workers 24/7 has not demonstrated
*dynamic* scaling.

## Treatment

The smallest depth-based scaler that tests the hypothesis:

```
python3 pilots/77b652487b4e/run_pilot.py --arm treatment --trace pilots/77b652487b4e/trace.json \
  --out pilots/77b652487b4e/results_treatment.json
```

Controller polls queue depth every 1 s; desired = clamp(ceil(depth / 2), 1, 6).
Scale-up: new workers begin consuming after a 1.5 s actuation delay (systemd-start
stand-in). Scale-down: only after desired < active for 5 consecutive polls, and a
stopping worker finishes its current task first (no task is killed). Floor of 1
worker models keeping one researcher alive for immediate pickup.
