- ticket: wq#1626 (build, p2) · agent `work-1626-0b0694`

- sibling: `MINERVA_STALENESS_REVIEW.md` (wq#1607, same day). That doc owns the

  This doc does not repeat it. It maps the WHOLE system (every store, including the

## 0. The finding in one paragraph

Lumen does not have one memory system with four layers. It has **22 stores** (16 on
disk, 6 tables inside minerva.db that behave as their own stores), fed by **14 writers**
on **9 timers plus one path unit**, and read by **three different boot paths** that do not
agree on what is authoritative. The bi-temporal store is declared the source of truth for
fleet facts in the session-start skill; `fleet-inv drift` prints "inventory YAML is truth"
about the same predicates; `HANDOFF.md` and `kb/SESSION-HANDOFF.md` are two handoffs
regenerated by different mechanisms and only one is read at boot; the federated prose
index that recall uses is 25 days behind the file it indexes; and the state store
contradicts itself across predicates on the one node Frank asked about this week
(`thoth.status` says offline since 09-02, `thoth.tailnet_routing` says fixed 09-08, both
current). None of this is a bug in any single store. It is the absence of a **fact-class
ownership contract**: for each class of fact there is no written answer to "which store
may assert this, and which stores are only allowed to project it." Sections 4-5 write that
contract and rank the moves that enforce it.

### 2.2 Path B — agent lanes (`lumen_agent_v4` → memoryd → `search_v3`)

Reads `archival_notes` (dense+lex+graph+entity, 6K cap) via `lumen-memoryd` on 127.0.0.1:8139. Does **not** read LIVE_FLEET_STATE, HANDOFF, instincts, or claude_memory.md (federated tier is off). A lane's picture of the fleet is whatever episodes mention it. State facts enter only indirectly, as subject anchors in `memory_edges`.

### 2.3 Path C — fworkers (foreman harness)

`prompt-forge/fleet_context.py` builds the roster deterministically from `lumen_state.py current` at request time (correct by construction, wq#957) + `projects/<slug>/STATUS.md` + `{{DISTILLED_MEMORY}}` (always empty, §1.17). The dispatch prompt then tells the worker to run Path A step 1-5 itself (UNIFIED_DISPATCH.md line 11) and `precheck` (line 77). So a worker pays Path A's 32K on top of its own context, and its own episode goes to a store Path A never reads.

### 2.4 On-demand paths (after boot)

- `lumen_state.py current <subject>` → 1.1 direct (the only path that sees topic-tier facts).
- `lumen_episode.py precheck/recall` → `search_v3` → 1.4 + 1.5 (+1.7 if flag on).
- `fleet-inv get/ssh-list` → 1.12a, bypassing 1.1 entirely for the ops scripts that reboot and rotate nodes.
- `fleet-search`, deep-research → 1.8.
- `context_selector.py "<query>"` → 1.9d ranked.

Three boot paths, four on-demand paths, and no two of them read the same set of stores.

2. **Projection without a trigger.** 1.2 (state-regen forgotten), 1.3 (own schedule), 1.7 (never re-run), 1.12b/c (never). A projection with no regen trigger is a hand copy with a generated header.
3. **Sibling-predicate staleness inside 1.1.** §3.2. 4. **Prose copies of structured facts.** claude_memory.md still carries 4 live-tense sentences about Nephthys serving embeddings/awareness outside any "was/retired" negation; the IP-only scanner cannot see them (wq#1607 §2.4). Every session block ("SESSION 2026-09-08") is a hand copy of queue.db + state at that moment.
5. **Duplicate artifacts with one name.** `HANDOFF.md` vs `kb/SESSION-HANDOFF.md`; `/home/lumen/FLEET_MAP.md` vs `foreman/research/FLEET_MAP.md`; `bin/wq` vs `agents/work-queue/wq` (already known); `archival/*.md` files vs `archival_notes` rows (24 orphan files).
6. **Copies outside the fleet's reach.** Frank's `<userPreferences>` hardware block and the three Anthropic-side skills carry IPs and hostnames that no fleet tool can regenerate. When the fleet moves, Frank has to edit them by hand — the REPEAT=FLEET DEFECT instinct fires on exactly this.
7. **Unaudited write paths.** `lumen_state.py ingest` and CLI `lumen_episode.py commit` write authoritative stores with no `memory_audit` row. memoryd's provenance guarantees cover lane commits only. A wrong fact cannot be traced to the session that wrote it except through free-text `source_ref`.

9. **Two embedders.** bge-m3 for sections (Path A), nomic for notes/federated/research (Paths B, on-demand). Not a correctness drift, but it is why 1.7 exists at all: recall could not read the section index because the vectors do not match.
10. **Dead write→read pairs.** 1.7 (written once, flag off), 1.10b (written every 30 min, read never), 1.17 (written every attempt, distilled never). Three stores where the pipeline is half-built and the half that exists costs cycles.

## 4. Consolidation design — one owner per fact class

### 4.1 The rule

For every class of fact there is exactly **one owner store** that may assert it. Every other
place it appears is either a **projection** (generated from the owner, with a trigger and a
`generated-from` header, never hand-edited) or **banned**. Hand copies of owned facts are
the defect class; every item in §3.3 is an instance of it. This is the same rule
`fleet_tools.yaml → FLEET_TOOLS.md` already follows (edit the YAML, render at read), and the
same rule `state_facts → LIVE_FLEET_STATE.md` was built to follow before the regen trigger
was left in a human's hands.

Nothing here changes the bi-temporal model, the proposal-only law for `claude_memory.md`
and `instincts.yaml`, or the retrieval weights measured on the frozen golden set. It changes
who is allowed to write what, and what regenerates when.

### 4.2 Ownership table

| fact class | owner | projections (generated) | banned hand copies | invalidation / re-verify rule |
|---|---|---|---|---|
| **observed fleet facts** — tailscale_ip, lan_ip, ssh user/key, kernel, os, versions, ram, storage layout, plug↔node, service unit state, lifecycle status | `state_facts` | LIVE_FLEET_STATE core/full · lumen_state.txt · inventory YAML `network:`/`hardware:`/`status.status` keys · FLEET_MAP.md · Frank's prefs block (rendered, handed to him) | prose sentences in claude_memory.md, HANDOFF §3, session blocks, ticket bodies | wq#1607 §3.2-3.6 (reconfirm-on-match, verifier registry, source_kind, staleness marks). Plus §4.3 sibling closure |
| **declared fleet config** — governance (crown_jewel, never_restart, off_limits), maint_tier, monitoring policy, intended roles, ops.known_issues | inventory YAML `machines/*.yaml` | Gatus sentinel config · `fleet-inv ssh-list` policy filter | state_facts rows for these keys | schema `check`; a declared key is true because Frank/orchestrator said so — no probe, but a change must cite a ticket in a `since:` field |
| **episodes / lessons / what-changed** | `archival_notes` | worklog.md · handoff verify top-6 · fq ledger (failed only) · foreman distilled facts (if ever built) | claude_memory.md "SESSION …" blocks, HANDOFF §2-3 narrative, fworker `episode.jsonl` as a terminal store | wq#1607 §3.7 (contradiction penalty, note_contradictions). The inventory row is the important split. `machines/*.yaml` keeps the keys that are *decisions*
and loses the keys that are *observations*. `fleet-inv get thoth network.tailscale_ip` keeps
working, because the projection regenerates those keys from `state_facts` into the YAML
(or `fleet_inventory.py` reads them from the store live, which is simpler and what
`prompt-forge/fleet_context.py` already does). `fleet-inv drift` then has nothing to
compare for observed keys and becomes a schema check plus a declared-vs-store check for
`status.status` only. The line "inventory YAML is truth" is deleted.

### 4.3 Predicate vocabulary and subject lifecycle (the thoth/nephthys class)

Supersession on `(subject, predicate)` is correct and stays. What is missing is that some
predicates are *about the same thing* and the store does not know it.

1. **Reserved predicate `lifecycle`** with a closed enum: `provisioning · active · degraded ·
   offline · decommissioned · retired`. `status` stays free-text for the story; `lifecycle`
   is what tools branch on. Backfill from the current `status`/`role` prose with a
   conservative map; ambiguous → `active` + a coverage line.
2. **Sibling closure on lifecycle change.** `ingest(subject, 'lifecycle', 'decommissioned'|'retired')`
   closes every *operational* predicate on that subject (`serving_model`, `embed_model`,
   `litellm_aliases`, `*_status`, `mcp_*`, `ollama_version`, `dc_handle_store`, …) with
   `valid_to = valid_from` of the lifecycle fact and `source_ref = 'lifecycle-closure:<id>'`.
   Identity/hardware predicates stay open (a decommissioned Mac still has 64 GB). The
   operational list lives in the verifier registry (wq#1613) as a `closes_on_decommission: true`
   flag per predicate, so it is data, not code.
3. **Predicate registry gate.** `ingest()` accepts a predicate that is in the registry, or
   one passed with `--new-predicate "<why>"`, and refuses the rest with the nearest existing
   name. This is what would have turned `thoth.tailnet_routing=FIXED` into a supersession of
   `thoth.status`, or at least made the writer say out loud that it is a new axis.
4. **Status-class facts must carry `valid_to` intent.** A `status` or `lifecycle=offline`
   fact is a claim about an interval; when the reconciler (wq#1608) sees the node up, the
   interval closes. Today an "offline since 09-02" row can outlive the outage by a week
   because nothing owns closing it.

### 4.4 Projection contract

Every generated artifact in §1 gets all four of:

| requirement | 1.2 LIVE_FLEET_STATE | 1.3 lumen_state.txt | 1.7 federated | 1.9d sections | 1.10 HANDOFF (gen half) | 1.12a inv observed keys | 1.12b/c manifest, FLEET_MAP | 1.13 FLEET_TOOLS |
|---|---|---|---|---|---|---|---|---|
| generator exists | ✓ | ✓ | ✓ | ✓ | ✓ (session-handoff) | build | wq#1615 | ✓ |
| trigger | **dirty flag set by `ingest()`, cleared by regen; `--core` regens if dirty** | same dirty flag | **hook onto `minerva-tag-sections.path`** (same source change) | path unit ✓ | timer ✓ + **read-time at `--core`** | dirty flag | timer + diff | read-time ✓ |
| `generated-from: <store>@<ts>` header | has ts, add source | add | n/a (rows carry `source_mtime`) | add to index.md | add | add | add | add |
| boot freshness check | **WARN if header ts < max(ingested_at)** | same | WARN if `federated_files.mtime` < file mtime | WARN if sections.json older than file | n/a (read-time) | WARN if drift | WARN if older than last survey | ✓ (path check) |

The dirty flag is one row in a tiny `projection_state(name, dirty, last_regen_at)` table in
minerva.db, written by `ingest()` in the same transaction. `state-regen` clears it.
`claude_context.sh --core` runs `state-regen --if-dirty` before the selector. That removes
"forgot to run state-regen" as a class: the human step becomes a fast path, not the only path.

### 4.5 One audited write path

- `lumen_state.ingest()` writes a `memory_audit` row (`table_name='state_facts'`,
  `action='write'|'supersede'|'reconfirm'`, `agent_id=$WQ_AGENT`, `source_ref`). Same table,
  same append-only triggers, zero new schema.
- `lumen_episode.commit` from a CLI session posts to memoryd `/commit` when the daemon is
  healthy and falls back to a direct write **that still writes the audit row** — the
  fail-open path keeps the trail. Today the fallback is the primary path.
- `source_kind` (wq#1607 §3.4) is stamped by the chokepoint from `$WQ_AGENT` + an explicit
  `--stated-by-frank` flag, never inferred after the fact.

Result: "who wrote this fact and from which ticket" is a query, on both authoritative stores.

### 4.6 Boot path unification

Path A becomes, in order: (1) verify block, (2) HANDOFF.md = generated in-flight header +
hand verbatim constraints, (3) FLEET_TOOLS, (4) instincts, (5) LIVE_FLEET_STATE core with
staleness marks (wq#1612) and **evidence-age eviction to the 4K cap**, (6) core prose
(target ≤ 8K after §5 phase 2 migrations), (7) ranked non-core to budget. Same script,
same order, roughly 20K instead of 32K, and every block either live or freshness-checked.

Path C (fworkers) stops re-running Path A inside the worker: `fleet_context.py` already
renders the roster; give it the generated HANDOFF header and the ticket's subject-scoped
state facts (`current <subject>` for each subject in the ticket's `memory_edges`) and drop
the "run claude_context.sh --core" line from the dispatch. Worker episodes go to
`archival_notes` via `lumen_episode.commit` at attempt end (§1.17), tagged `lane=<lane>`,
which memoryd already knows how to trust-derive from the claim.

Path B (lanes) gains one thing: subject-scoped state facts for the ticket's subjects,
injected ahead of recall within the existing 6K cap. Lanes currently learn fleet state only
from episodes that happen to mention it.

### 4.7 One embedder (decision to measure, not to make here)

Sections use bge-m3, everything else nomic. Two options, both measurable against the frozen
golden set and `context_selector --rank` probes:

- (a) re-embed `sections.json` with nomic → `search_v3` reads sections directly, 1.7
  federated_chunks retires (its chunking and header-context were the value-add; that can be
  kept as the section chunker). One model resident, one vector format.
- (b) keep bge-m3 for sections, accept 1.7 as the bridge, but re-trigger it (§4.4).

(a) is cleaner; (b) is cheaper this month. Either is fine; two embedders with one of the two
indexes dead is not.

### 4.8 The outbox

Proposal-only stays law. What changes: the outbox gets a **reader**. A weekly digest
(`dream-digest`, appended to the Sunday dream run) lists every unapplied plan with its age
and a one-line apply command, posts it to `lumen-briefing`, and opens ONE wq user-lane
ticket that supersedes last week's. Exact-duplicate merges (`method=exact-auto`,
cosine ≥ 0.98) may auto-apply — they already have their own `apply_merge_plan(exact_only=True)`
path and are not memory edits in the sense the law protects.

## 6. What already works — do not break it

- Deterministic supersession, invalidate-never-delete, the out-of-order guard, read-time-only
  decay (wq#1607 §5 in full).
- `minerva-tag-sections.path` → sections.json: the one projection with a working
  source-change trigger. §4.4 copies it, does not replace it.
- `fleet-tools-render` at read time: the pattern for HANDOFF's generated half.
- `prompt-forge/fleet_context.py`: roster correct-by-construction from the store. It is the
  existing proof that Path C can read `state_facts` directly; §4.6 extends it.
- pgvector `content_hash + mtime + delete-reconcile`: unchanged.
- memoryd trust derivation from the wq claim and the provenance-immutability trigger:
  §4.5 routes more writes through it, changes nothing in it.
- `W_REC = 0.00`, the frozen golden set and its sha, the trap@1 alarm. Every retrieval
  change above is measured against them or does not ship.
- Proposal-only for `claude_memory.md` and `instincts.yaml`. §4.8 adds a reader, not a writer.
