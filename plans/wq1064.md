## Proposed Change

Two-step, because the acceptance criteria requires root cause, not just an ack
+ restart, and a simultaneous trio-wide failure right after a shared-file edit
smells like a regression rather than three independent crashes:

**Step 1 — root-cause check (read-only, run first, from a session with real
fleet access):**
```
systemctl status lumen-planner lumen-generator lumen-evaluator --no-pager -l
journalctl -u lumen-planner -u lumen-generator -u lumen-evaluator --since "2026-08-28 06:00:00" --no-pager
python3 -m py_compile /home/lumen/autonomy/agent5/a5_common.py
```
Look specifically for an ImportError/SyntaxError/traceback pointing at
`a5_common.py` around the service start attempts, and for the exit reason
(`systemctl status` "Main PID exited, code=exited" line) to distinguish a code
regression from an unrelated crash (OOM, disk, network to LiteLLM, etc.).

**Step 2a — if journalctl shows a clean, unrelated crash (OOM/transient) with
no import error:** standard restart, the same one used in wq#1020 and
prescribed by wq#206's runbook note:
```
sudo systemctl restart lumen-planner lumen-generator lumen-evaluator
```

**Step 2b — if journalctl shows an import/syntax error tracing to the
2026-08-27 22:45 UTC `a5_common.py` edit:** revert that file from its
pre-edit backup before restarting (the backup already exists per wq#1022):
```
cp /home/lumen/autonomy/agent5/a5_common.py.bak.20260827_224516 /home/lumen/autonomy/agent5/a5_common.py
sudo systemctl restart lumen-planner lumen-generator lumen-evaluator
```
then re-open a follow-up ticket for wq#1022's key-fallback fix to be redone
without the regression, rather than silently losing that fix.

Do not restart blind without running Step 1 first — that's the difference
between "root cause fixed" and "papered over," which the ticket's acceptance
criteria explicitly calls out.
