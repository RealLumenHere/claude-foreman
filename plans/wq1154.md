## Proposed Change

Make `probe_maat_vault` read the same source of truth the HA automation itself uses
(`/home/lumen/ha/primary` + `/home/lumen/ha/ha.env`) instead of hardcoding Ma'at's
address, so it checks whichever node is *actually* serving right now — implementing the
design `wq#294` already specified and that was never applied.

In `/home/lumen/sentinel/probes/sentinel_probes.py`, replace the `MAAT_ALIVE` constant
and `probe_maat_vault()` (current lines ~666–679) with:

```python
HA_DIR = Path("/home/lumen/ha")
HA_ENV = HA_DIR / "ha.env"
HA_PRIMARY = HA_DIR / "primary"

def _ha_env_var(key):
    try:
        for line in HA_ENV.read_text().splitlines():
            line = line.strip()
            if line.startswith(f"{key}="):
                return line.split("=", 1)[1].strip().strip('"').strip("'")
    except Exception:
        pass
    return None

def probe_maat_vault():
    """Vaultwarden /alive on the CURRENT vault primary (Ma'at or its promoted
    standby), per /home/lumen/ha/primary -- the same source of truth
    wadjet-ha-monitor.sh itself uses. wq#1154/aq#967: the prior verbatim port
    (wq#969) hardcoded Ma'at's own address, so it stayed CRITICAL through a
    successful auto-failover (the wq#294 finding, never applied). Note:
    VAULT_ORIGIN_WADJET is a legacy name -- it has pointed at Sobek since
    2026-08-10 (aq#429), not the physically-retired Wadjet box."""
    primary = HA_PRIMARY.read_text().strip() if HA_PRIMARY.exists() else "maat"
    origin_var = "VAULT_ORIGIN_MAAT" if primary == "maat" else "VAULT_ORIGIN_WADJET"
    origin = _ha_env_var(origin_var)
    if not origin:
        return False, f"cannot resolve {origin_var} from ha.env (primary={primary})", True
    try:
        t = time.time()
        st, _ = _http(f"{origin}/alive", timeout=8)
        ms = round((time.time() - t) * 1000)
        if st == 200:
            return True, f"primary={primary} {origin}/alive 200 ({ms}ms)", False
        return False, f"primary={primary} {origin}/alive HTTP {st}", True
    except Exception as e:
        return False, f"primary={primary} {origin}/alive unreachable: {type(e).__name__}: {str(e)[:80]}", True
```

## Risk Assessment

- **Blast radius**: one probe function in `sentinel_probes.py`, read-only (an HTTP GET to
  `/alive`), invoked only by `sentinel-probes.timer` every 30 min. It cannot mutate any
  fleet state, restart anything, or affect other probes in the same file (isolated
  function, no shared state beyond the module-level `Path` constants being added).
- **Main risk**: `ha.env`'s actual quoting/format differs from what's assumed here (e.g.
  values wrapped in quotes differently, or the var name is spelled differently than
  inferred from `wadjet-ha-monitor.sh`/`wadjet-ha-failback.sh` references). Mitigated by
  reading the real file at apply time (not possible from this sandboxed diagnosis
  session — `guard.sh` denies it) before finalizing the parser, and by `py_compile` +ing
  a manual dry run (Verify Command) before relying on the timer's next cycle.
  Worst case if wrong: `probe_maat_vault` returns `(False, "cannot resolve ...", True)` —
  a CRITICAL page, same failure mode as today, not a *new* outage class, and it
  self-documents the exact cause in the Gatus/aq detail text for the next pass to fix.
- **Ma'at being down is a real, ongoing 6.5h+ outage** independent of this fix — this
  change does not touch Ma'at, does not attempt any repair of it, and does not change
  failover behavior; it only corrects what the probe *reports* once failover has
  occurred. If Frank wants Ma'at physically checked, that's a separate, physical-access
  ticket (see Current State) — leaving it open here does not block or worsen this fix.
- **Sentinel-probes' ~5h timer gap today** is also untouched by this change — separate
  defect, separate ticket.
- Net: low risk, narrowly scoped, matches an already-reviewed and previously-recommended
  design (wq#294) that just was never wired up.
