# ops bundle deploy-vs-retire register (wq#2985)

wq#1732 audited all 92 `foreman/ops/` bundles carrying an `install.sh` and left 36
PENDING with no owning ticket. This is the disposition for those 36, and the rule
for anything that lands in the same state later.

The table below is **generated** — `python3 ops/deploy_triage.py --markdown`. Edit
`ops/deploy_triage.py`, never this file's table. `--check` re-derives every live
signal the register rests on and exits 1 when one has rotted; `ops/tests/
test_wq2985_deploy_triage.py` runs the same assertions in CI.

## The one rule this ticket produced

**ABSENT is not a disposition.** wq#1732's verdicts came from a content-hash index
over 13 fixed local roots (`ops-deploy-drift` `ROOTS`). That index reports ABSENT
for three kinds of bundle that are fully deployed:

| blind spot | example | what a blanket deploy would have done |
| --- | --- | --- |
| install root outside the index (`/opt`, `/home/sia`, `/usr/local/lib`) | `wq2472-vlogs-fleet-rollout` | reinstalled a forwarder running on 7 nodes |
| target on another fleet node | `wq2286-gitea-secret-scan` (Anubis) | re-pushed pre-receive hooks onto a live Gitea |
| payload live under a renamed unit | `wq858-trivy-weekly-scan` (`lumen-trivy-weekly.timer`) | added a second weekly scanner and overwritten `/usr/local/bin/trivy` mid-flight |

And one more the index cannot see at all: `wq1396-minerva-proposal-promoter` reads
ABSENT because its own `install.sh:7-11` refuses to run — wq#1500 replaced it, and
running both double-files every CVE proposal.

So every disposition here rests on a second signal the index cannot fake: a unit
read back from `systemctl list-unit-files`, a marker in the live file, or an `ssh`
query to the node that actually runs the payload.

## What "verified" now means

All 36 bundles answer `install.sh --verify` per `VERIFY_CONTRACT.md` (23 handlers
added by this ticket). For a KEEP bundle the handler proves the payload is live.
For a RETIRED or SUPERSEDED one it is inverted — it proves the replacement is live
and the retired names stayed absent — so a future audit cannot resurrect the bundle
off an ABSENT verdict the way this one nearly did.

`ops/_verify.sh` gained `vremote_up` / `vremote_file` / `vremote_unit` for the
bundles that install onto other nodes. An unreachable node is `ERR` (exit 2), never
`MISS`: "I could not look" must not read as "it is not deployed", which is the
whole failure this register exists to prevent.
